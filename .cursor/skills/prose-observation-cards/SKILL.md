# prose-observation-cards（読み味・観察用例）

Skill = **任意観察の手順**＋現役カードの正本管理。  
合否エンジンではない。L1必須（§4.3.1）や全文推敲（`toolarc-ja-prose`）の代替にしない。です／ます3連続は L1でも任意観察（必須合否ではない。リズム切断だけの短文メタを増やさない）。

| 層 | パス | 役割 |
|----|------|------|
| 本 Skill | このファイル | スキャン手順・上限・改修ゲート・呼び出し |
| 現役カード | [`references/active-cards.md`](references/active-cards.md) | **最大3組**。L1実行時はここだけ読む |
| L1ゲート | `l1-review-article` | 合否。本Skillへポインタ（詳細は持ち込まない） |
| 推敲適用 | `toolarc-ja-prose` | 深い書き換え。本Skillのカードを合否に使わない |
| 文体正本 | `docs/ai-context/writing-rules.md` | 文体6ルール。本Skillは複製しない |

## やること / やらないこと

**やる**

- 導入1〜3段落の読み味スキャン（任意改善用）
- `vocab-echo-01` 対象の above-the-fold（description + 導入 + 今日の結論）の同義ラベル反復
- 対象が導入以外の現役カード（例: `block-redundant-01`）は、本論で同型に気づいたら任意改善へ（全文推敲はしない）
- 現役カード（最大3）を観察の校正器として使う
- 人間承認後のカード／手順の最小改修。誤検知は人間レビューで適用外・用例を育てる

**やらない**

- カードを根拠にL1不合格にする
- 現役4組目の追加（上限見直しは別タスク）
- 記事全文・長い経緯の貼り付け
- `toolarc-ja-prose` 手順の複製
- 人間承認なしのカード新規追加
- `posts.ts` / 公開 / 収益導線の変更

## 呼び出し（L1から）

`l1-review-article` の合否のあと（または任意改善を書く直前）:

1. 本 Skill を読む
2. [`references/active-cards.md`](references/active-cards.md) の**現役だけ**読む（履歴・Vault退避は読まない）
3. 下の「導入読み味スキャン」を実施。対象が導入以外の現役カードは、本論で同型に気づいたときだけ任意改善へ（広読しない）
4. 結果は **任意改善** に書く（必須修正にしない。本文へ自動適用しない）
5. 導入に問題なしなら「導入読み味: 所見なし。理由: …」を1行必須（空欄禁止）。本論のカード指摘は別行

token例外: 同 `contentId` の直近公開1本の**導入3段落まで**比較してよい。それ以外の広読はしない。

## 導入読み味スキャン

対象: 記事の導入1〜3段落（H1直後〜「今日の結論」の手前が目安）。  
`vocab-echo-01` は **above-the-fold**（`description` + 導入 + `> **今日の結論**`）を見る。  
例外: 現役カードの「対象」が導入以外なら、本論で同型に気づいたときだけ見る（合否にしない。全文は読まない）。

観点:

1. **保険の読点** — 読点は列挙・条件・対比のどれか説明できるか
2. **助詞の保険** — 「を／が／は」が情報の新出に寄与しているか。省略した方が一息で追えるか
3. **山場前の減速** — 体言止め・短い常体の直前が、助詞・読点で鈍くなっていないか
4. **シリーズ温度** — 同contentId直近1本の導入と口語／書き言葉の温度が極端にずれていないか（ある場合のみ）
5. **同一ブロックの意味重複** — 同じ段落／ブロックで、すでに書いた意味をラベルだけ重ねていないか（`block-redundant-01`）
6. **同義ラベルの短距離反復** — above-the-fold で役割・スコープを同語幹で言い直していないか（`vocab-echo-01`。固定語カウントは使わない）

出し方:

- 指摘は要素名つきで1〜3件（例: 「保険の読点: …」「同義ラベル反復: …」）
- 現役カードと同型ならカードIDを添える（例: `intro-comma-01` / `block-redundant-01` / `vocab-echo-01`）
- 本文への自動適用はしない（任意改善＝人間が採否）。誤検知の見送りはトリガーC → 適用外を足してカードを育てる

## 現役カード上限

- 現役 **最大3組**（正本: `active-cards.md`）
- L1は現役のみ読む
- 4組目需要 → 統合／退避を先に検討。不可ならAI-logに上限見直しを起票して**停止**（黙って4組目を現役化しない）

カードID: `{scope}-{topic}-{連番}`（例: `intro-comma-01`）。退避済みIDは再利用しない。

## 改修ループ（人間承認後のみ）

詳細の設計経緯は当日AI-log可。運用の要約のみここに置く。

### トリガー

| ID | いつ |
|----|------|
| A | L1後に人間が本文を追加修正（必須では説明できない差分） |
| B | L1任意改善を人間が本文に採用 |
| C | 任意改善を見送り、かつ「観察ズレ／誤検知」と明示 |
| D | 任意が有用だが既存カードの観察語に無い |

必須修正だけ・好みだけで要素名化できない差分・「とりあえず4組目」はトリガーにしない。

### 採用ゲート（すべて必須）

1. L1必須では捕捉できない（任意レイヤ）
2. 差が**要素名**で説明できる
3. 既存現役と観察語が実質重複しない（重複なら統合・精錬）
4. §4.3.1必須合否にしないと明記できる
5. 人間が「Skillに反映してよい」と承認した

### 更新タイプ（主タイプは1つ）

| タイプ | 編集先 |
|--------|--------|
| T1 新規カード | `active-cards.md`（既に3なら先にT4） |
| T2 既存精錬 | 同ファイル（枚数増やさない） |
| T3 手順のみ | 本 `SKILL.md` の観点・適用外・呼び出し |
| T4 統合／退避 | 2→1、または1組をAI-log／Vault履歴へ |
| T5 適用外追加 | カードまたは本Skillの「見ないもの」 |

T2+T5は可。T1+T3は人間が明示したときだけ。

### 承認後の編集手順

1. `Get-Date -Format "yyyy-MM-dd HH:mm"`
2. `active-cards.md` および／または本 `SKILL.md` を最小差分更新
3. 当日AI-logに `## prose-observation-cards 改修`（タイプ・要約・現役ID一覧）
4. `l1-review-article` / §4.3.1 / 記事MDはポインタ切れがなければ触らない
5. commit/PRは人間依頼時のみ

### 流れ（短縮）

```text
α: L1 → 人間が導入修正(A) → 要素名をAI-log固定 → 承認 → T1/T2 → 次L1で確認
β: L1任意 → 人間が採用(B) → 要素名化 → T1/T2 または T3
γ: L1任意 → 見送り＋観察ズレ(C) → T5 または T3（カードを安易に増やさない）
δ: 成長前提カード（例: block-redundant-01）→ 採用例はT2で用例追加、誤検知はC→T5。枚数は増やさない
```

## 完了報告

**スキャン時**: 任意改善の件数 or 「所見なし＋理由」／参照したカードID  
**改修時**: タイプ（T1〜T5）／触ったファイル／現役ID一覧／AI-log追記の有無
