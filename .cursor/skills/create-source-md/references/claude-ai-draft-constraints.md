# ToolArc — Claude.ai 本文初稿用・共通制約

**用途**: web版 Claude.ai（スロット④）で記事本文初稿を書くときの **共通ルール**。  
**置き場（正本）**: `toolarc-web/.cursor/skills/create-source-md/references/claude-ai-draft-constraints.md`  
**運用**: 本ファイル（または同内容）を Claude.ai Project の知識／カスタム指示に読み込ませる。各記事の **source.md には共通節を埋め込まない**（記事差分のみ）。

詳細の正本（Cursor／リポジトリ側）:

- `docs/ai-context/writing-rules.md`
- `docs/ai-context/llm-forbidden-phrases.md`

本ファイルは運用に必要な要約。リポジトリ全文の代替ではない。

---

## 添付の仕方

1. **本共通制約**（Project 知識または毎回添付）
2. **当該記事の `source-{slug}.md`**（構成・ゲート・記事差分）

source だけ、または本ファイルだけで書かない。両方を前提にする。

---

## Frontmatter（初稿先頭の型）

source に書かれた title / description / tags / target を使う。キー構成:

```yaml
---
title: "…"
description: "120〜160文字必須（両端含む。①で Unicode 再実測）"
date: YYYY-MM-DD
tags:
  - …
site: toolarc.jp
target: "ペルソナを要約した想定読者1行（source の Output Contract 項目1と同文）"
---
```

- title と H1 は検索意図を一致（H1 は title と同文でよい）
- `date` は公開①が確定するのでプレースホルダ可
- `――` / `——` 禁止。区切りは `｜` または `：`
- `target` はペルソナ表の別軸ではない。公開・初稿にペルソナ表は転載しない

---

## 読者最優先（合否の最優先）

- 執筆の実況・姿勢宣言のメタ短文（「断定は避ける。」等）を増やさない
- 境界は事実で書く（例: 本記事では設定手順は扱いません）
- 「続きの記事へ」誘導を結論・導入・本論の答えにしない
- 着地意図は当該記事内で完結させる

---

## 文体・形式

- 敬体（です・ます）ベース。段落の最後の文は必ず敬体で閉じる
- です／ます3連続の切断は必須にしない（リズム目的の短文メタを足さない）
- 体言止めは段落の途中の山場のみ。短い常体の断定は山場のみ可
- 一文の長さをばらす（短→長→短）
- 一人称: 「私」「当サイト」禁止。「筆者」は実測・確認範囲の限定を示す文だけ
- 結論の先延ばし禁止。「今日の結論」を導入直後に置く
- 1段落1トピック。「状況→理由→対策」の同一テンプレを連打しない
- 因果には機構を一文添える
- 推測は「〜と考えられる」「〜の可能性」。「絶対」「必ず」「標準」の断定禁止
- 英語用語は初出で日本語を添える

## LLM空句（類型のみ。語彙正本は llm-forbidden-phrases）

避ける。言い換えるか削る。

- 空の強調だけで論を進める: 「重要なのは」「不可欠」「欠かせない」
- 根拠のない作業実況: 「掘り下げる」「深掘りする」
- 中身のない網羅語: 「多角的」「包括的」「総合的に」
- 接続の連打: 「さらに」「また」「加えて」を短文で連続
- 文中・見出しの `――` `——`（句点分割・問い・「そのあと」等へ）
- 括弧の入れ子: `（「…」）` 等は不可。括弧内の強調は `"…"` か `` `…` ``。未公開は `「準備中」`
- 「早道」は使わない（「近道」へ）

「最後に」「まさに」は禁止しない。禁止語の機械的回避より、文長・段落の均質さを崩すことを優先する。

---

## 句読点・Markdown

- `（…）。` `」。` の句点重ねをしない。`「…です。」` の会話体クローズも不可
- 対応関係・一覧は Markdown 表を優先
- 太字は要点の語句のみ。段落全体を太字にしない
- 内部リンクは `/blog/slug` のみ。source に無い URL を捏造しない
- 未公開記事は「準備中」と書き slug・URL を出さない
- 画像は source の指示があれば alt 付きプレースホルダ可。生成・配置は別工程

---

## 公開面語彙（一般ルール）

- source の役割ラベル（入口・本編・地図・正本・委譲・専念 等）は編集室内語
- 公開本文（description・導入・今日の結論）に同じラベルをそのまま繰り返さない
- 意味は保ち、source の「公開面語彙メモ」の言い換え候補で分散する（固定語の回数制限は設けない）

---

## スキャン層・暦日

- 見出し・挿絵・太字だけで概要が辿れるよう書く
- 太字は分岐軸／記事スコープ／よくある誤解の否定／固有名に限定
- 暦日は免責の `執筆時点（YYYY-MM-DD）` に1回あれば足りる。本文・結論は「執筆時点」で範囲限定可。各 H2 に同じ暦日を繰り返さない

---

## 共通のやらないこと

- 隣接記事の全文転記
- 未確認仕様・料金・画面名の断定
- source に無い URL の捏造
- 未公開 slug の露出・偽リンク
- ペルソナ表の本文転載
- 直アフィ方針違反（source の収益導線案に従う。収益なら `policy.ts` 準拠）
- `posts.ts`・公開・PR・リポジトリ操作の指示を本文に書かない
