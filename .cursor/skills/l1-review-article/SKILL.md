## 合否の優先順位（厳守・2026-08-25）

1. **読者最優先**（ペルソナ充足＋「今知りたいか／今クリックしたいか」）を**最初**に判定する
2. そのあと Output Contract・根拠・誇大・slug／リンク形式・免責形式など他の必須
3. **です／ます3連続・リズム切断は必須修正にしない**（任意改善のみ。ブロックまたぎはさらに緩く・原則見送り）
4. リズム切断のためだけの短い常体・執筆メタを増やして「直した」ことにしない（品質低下の主因）

## やること / やらないこと

**やる**: 読者最優先を先頭にした項目別合否、任意観察（導入読み味＋対象が広いカード＋任意の文末リズム）、必須修正の記事MD適用（最小差分）、AI-log への「L1レビュー実施」節追記、①への引き継ぎ文  
**やらない**: `posts.ts` / `series.ts` 登録、`npm run build`、公開日確定（すべて①＝`publish-article`）、全文初稿の作成（④のProduceは別）、GSC（②）、PoE2/api、全記事の一括再レビュー、読み味カードを根拠にした不合格判定、**です／ます3連続の必須修正／自動適用**、リズム目的だけの短文常体・執筆メタの増殖、記事末免責をです／ます理由で直すこと（免責形式・見出し化・`」。` は従来どおり見る）

## 手順

開始時: `Get-Date -Format "yyyy-MM-dd HH:mm"` → 編集した Vault ファイルの `Last Updated`／記録の実施日時に使う（手入力・推測禁止）

0. **判定の前（機械検索・必須）**: 項目別合否の前に、対象記事MDへ次を実行する。詳細基準は `writing-rules.md` / §4.3.1（本Skillへルール本文をコピーしない）。ヒットは**必須修正**。
   - 本文を `」。` で検索する。当たったら閉じ `」` の直後の句点を外す（`」` の直後から次の文）
   - 本文を `）。` で検索し、文末の `（…）。` 重ねがあれば句点を外す
   - 導入1〜3段落（H1直後〜「今日の結論」の手前）の**各段落の最後の文**が敬体か見る。常体・体言止めで閉じているなら敬体に直す。表・箇条・コードブロックは除外
   - 本文・見出し・`title` を `弱リンク` / `Output Contract` / `カニバル` で検索する。ヒットは編集室内語の公開面漏れとして**必須修正**（言い換えか削除。詳細は writing-rules「読者最優先」）
   - **ここでです／ます3連続の機械スキャンを必須修正に使わない**（任意観察へ回す）

1. **読者最優先（必須・最初に合否）**: §4.3.1 項目13／writing-rules「読者最優先」を開き、次を ✅／要修正 で判定する。AI-logにペルソナ名と過不足を短く残す（source由来かL1補完かも1語）。
   - **ペルソナ充足**: source.md にペルソナ2〜3があればそれを正とする。無ければ想定ペルソナ2〜3を立てる。各々の知りたいメイン・着地の求め・不足の充足。全ペルソナのメインが揃っていなければ要修正。境界外は充足義務外
   - **「今知りたいか」フィルター**: 各段落・リストが事実・手順・判断材料か。執筆メタ（例: 「断定は避ける。」「まず要点だけ置きます。」「本記事は安全判定しない」）やリズム切断だけの短文は読者価値に数えない → 必須修正で削る／事実の線引きに言い換える／免責へ移す
   - **内部リンク**: 着地意図の完結／「今クリックしたいか」／用語の公開面／出口の場所。冒頭リンクの一律禁止はしない。Hub／シリーズ入口は地図としての誘導を不合格にしない
   - **サブ情報 +α**: 不足は任意改善のみ（合否にしない）

2. **その他の必須合否**: 次を ✅／要修正 で判定する（正本は §4.3.1 **必須**。詳細は `writing-rules.md` / `llm-forbidden-phrases.md`。本Skillへコピーしない）。
   - Output Contract 8項目（writing-rules「Output Contract」）
   - 文体のうち**必須に残るもの**: 段落末敬体・見出し・免責形式（writing-rules）。`」。`／`）。` は手順0済み。**です／ます3連続はここでは合否しない**
   - LLM空句（`llm-forbidden-phrases.md`）連打の有無
   - 一次情報／根拠バー要件（writing-rules）。公開見出しに内部判定語を出していないか
   - 追加観点: 誇大・未確認断定なし／slug 3点一致／内部リンク `/blog/slug` 形式／rich-toc なら `<!-- embed:* -->` 維持

3. **任意観察（合否にしない）**: Skill `prose-observation-cards` を開き、その手順どおり実施する（導入が主。対象が広いカードは本論の同型1件まで可）。加えて文末リズムは次のとおり。
   - 現役カードは `prose-observation-cards/references/active-cards.md` のみ読む（最大3。履歴は読まない）
   - **です／ます3連続（任意）**: 同一段落内は任意改善に挙げてよい（優先度は読者最優先より低い）。**段落・H2・リストと本文のまたぎ**は任意に残してよいが**修正要否は一段緩く・原則見送り／「優先度低」と明記**。読者がつまずく明確な均質さがあるときだけ提示。**自動適用禁止**。リズム切断のための短文常体を新規挿入しない
   - 結果は **任意改善** に1〜3件＋必要ならです／ます任意。導入に問題なしなら「導入読み味: 所見なし。理由: …」を**必ず**書く（空欄禁止）
   - 読者最優先のサブ情報 +α の不足があれば、任意改善に1行足してよい（カード枠とは別）
   - 本文への自動適用はしない。カード／です／ますを根拠に手順1〜2を不合格にしない。誤検知の採否は人間（カード育成）
   - 要推敲が2件以上、またはユーザーが文体を明示優先した場合 → 任意改善に「`toolarc-ja-prose` で導入のみ再スキャン」を1行残してよい（L1内で全文推敲しない）

4. **必須修正**: 記事MDへ直接適用（最小差分・全文書き換え禁止）。**任意改善は提示のみ**とし、適用可否をユーザーに確認する。です／ます切断・記事末免責をリズム理由で書き換えない

5. **記録反映**:
   - 当日 AI-log に「## L1レビュー実施：<記事タイトル>」節を追加（実施日時・**読者最優先を先頭にした**項目別合否・必須修正・任意改善・総合判定・①への引き継ぎ）。転記先が「# Claudeで記事作成：<inbox名>」の直後にある場合はその近くに置く
   - 任意改善欄は省略禁止（上記「所見なし＋理由」可）。総合判定の近くに「任意改善の提示: あり / 所見なし（理由付き）」を1行書いてよい
   - **該当タスクがある日だけ**: 改善施策ノート §8 の該当項目を Done 条件確認後に `[x]`、実行ログへ時系列エントリ＋進捗サマリー更新

6. **完了報告（短く）**: 読者最優先の合否／適用した修正／未適用の任意改善（読み味・です／ます任意含む）／①への1行引き継ぎ

## 厳守

- 日時は Get-Date 取得値。編集した Vault ファイルの `Last Updated` を同値で更新。未編集ファイルは触らない
- Vault内リンク・公開記事リンク・記号入り見出しの扱いは個人 Skill `obsidian-markdown` の「ToolArc constraints」に従う（アンカー推測禁止。記号入り見出しへリンクする必要があれば見出し改名案を出し、ユーザー承認後に改名）
- 公開記事リンクは `/blog/slug`。未公開は「準備中」、slug未確定ならリンクしない
- frontmatter `date` は仮値のまま（①が実装日で上書き）
- **読者最優先を文体リズムより先に見る**。です／ます3連続は必須修正にしない（§4.3.1／writing-rules）。ブロックまたぎはさらに緩く
- リズム切断のための短文常体・執筆メタを必須修正として増やさない
- 記事末免責をです／ます理由で直さない（形式・見出し化・重ね句点は対象のまま）
- token節約: 対象記事・当日AI-log・§4.3.1・空句リスト・`prose-observation-cards`（SKILL＋現役カード）以外は読まない。広範囲探索は実行前に確認
- token例外: 導入読み味のシリーズ温度比較のため、同 `contentId` の直近公開1本の**導入3段落まで**読んでよい。読者最優先のため source.md（当日フォルダの当該slug）は読んでよい
