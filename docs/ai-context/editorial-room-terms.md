# 編集室語リスト（公開面禁止）

最終更新: 2026-09-24 17:40

**用途**: 公開記事（`title` / `description` / 見出し / 本文）に出してはいけない**編集室内の運用語・役割ラベル**、および L1／人間差し戻しで確定した**造語・難解フレーズ**の語彙正本。  
**方針の正本**: [`writing-rules.md`](./writing-rules.md)「読者最優先」→ 用語の公開面／言い直しテスト。  
**使う場所**: L1手順0の機械検索、Claude.ai 共通制約の公開面語彙、初稿・リライト時の自己チェック。

## 運用

### いつ追加するか（トリガー）

記事レビュー（L1後の人間差し戻し含む）で、次のいずれかに当たったら **同じ作業セッション内** に本ファイルへ追記する（記事修正だけで終わらせない）。

- 「意味が分からない」「全く分からない」「伝わらない」
- 「日本語として不自然／造語」
- 「編集室の言葉／読者向けでない」
- Agent の言い直しテストで必須修正し、**再発防止のため語・フレーズを固定したい**とき（人間が同意／指示したとき）

### 追加手順（Agent）

1. `Get-Date -Format "yyyy-MM-dd HH:mm"` で本ファイルの `最終更新` を更新する
2. **語**なら §1、**フレーズ／比喩**なら §2 に1行追加する（言い換え例＋根拠＝日付と AI-log／指摘要約）
3. §5 取り込みログに1行追記する
4. 当日 AI-log に「editorial-room-terms 追記: ＜語／フレーズ＞」を1行残す
5. 誤検知が多い語（例: 「入口」）は §1 に入れず §3 扱いを検討する。暦日・免責定型は §4 の除外を崩さない

### その他

- 運用docs・source.md・AI-log・week-queue では使ってよい
- **禁止するのはラベル／造語の公開面露出**であって、Hub／シリーズ入口へ誘導すること自体ではない（誘導文は日常語で書く）
- 根拠ログ: AI-log の L1必須修正・人間指摘ラウンド（特に 2026-09-16 A〜L、2026-09-12、2026-08-13 等）

## 3. 「入口」の扱い（誤検知注意）

- source／運用ラベルとしての **単独の「入口」**（記事役割の内部ラベル）は公開面の主役にしない（Claude公開面語彙・source公開面語彙メモ）
- ただし人間差し戻しで採用した **「シリーズ全体の入口」「シリーズ入口」** は、地図ラベルの**正しい言い換え**であり、禁止しない
- **「公式ドキュメントの入口」** は禁止（§2「ドキュメントの入口」。案内ページ／開始ページへ）
- 機械検索で `入口` を単独ヒットさせると誤検知が多い → **手順0の固定スキャン語には入れない**。役割ラベル疑いは言い直しテスト／文脈判定

## 4. 意図的に含めないもの

- `Hub` / `Client` / `Server` / `MCP` など、読者の製品・画面文脈で通じる固有名
- 記事末**免責**ブロック内の定型（`執筆時点（YYYY-MM-DD）` 等）
- 本文の「執筆時点」「暦日」そのもの（時期が重要な記事があるため、リスト禁止にしない。description の「執筆時点の情報」だけ上表で禁止）
- 「範囲」単独（2026-09-16 人間Dは回数確認のみ。一括禁止にしない）。「確認した範囲」→「確認した内容」は当該文脈の言い換え例
- 「認識」→「登録」のような**記事内用語揃え**（編集室語ではない）
- 「破壊的操作」（ファイルが消える・上書きされる区分。2026-09-18 013で公開面使用を確定）。API互換の「破壊的変更」も禁止しない。禁止するのは区分ラベルの「破壊的」単独と「要注意（破壊的操作）」の二重注意
- 「スコープを明示」「明示的に実行」（設定の指定・手順の事実。禁止するのは読者向けの「明示します」）
