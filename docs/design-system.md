記事共通の表示は、承認済みサンプルAの読みやすさ・情報整理を基準にする。白黒だけの紙面や純白の背景色へ固定せず、明るい本文を土台にToolArcらしい配色と視線の誘導を検討する。今回のユーザー指示は、記事ページで下記の範囲に限り、従来の「ソフトブルー・淡い面・角丸を多用する」見せ方に優先する。サイト全体やトップ・記事一覧・静的ページの配色を一括変更する指示ではない。現在の本番は従来表示。N36は11/15にローカル実装と表示確認まで進み、PR/公開は未実施。

## 読みやすさ・関心・選択を分けて設計する（2026-11-14追加承認）

白ベースは読みやすい本文を作る土台であり、訴求や収益性を保証するものではない。A案の情報整理を保ちながら、次の3つの役割を色・画像・見出し・配置・余白で支える。

| 役割 | 見せ方 |
|---|---|
| 読み進める | 明るい本文背景、濃い文字、適切な本文幅・行間・余白 |
| 興味を持つ | 公式画像、具体的な利用場面、内容が分かる見出し |
| 自分に合うと判断する | 用途別おすすめ、比較と金額差、次の行動 |

色だけで訴求を解決しようとせず、重要な画像や答えが最初にどの順で見えるかを確認する。サイト名の大きな帯を目立たせるためだけに復活させない。目立つ囲みが広告のように読み飛ばされる可能性も考慮する。以下は11/15に同じ内容・同じ画面幅で比較する配色/構成の候補であり、色値や濃色冒頭の本番採用を確定したものではない。

| 比較候補 | 狙い・確認点 |
|---|---|
| 温かみのある白＋墨色＋深い青緑 | 優先して試す候補。落ち着いた編集媒体らしさと識別できる色を両立。文字/リンク/フォーカスの見分けやすさを確認 |
| 白＋濃い青＋少量の暖色 | 技術情報としての明快さと判断箇所の強弱。既存の青を整理した比較対象とする。役割のない多色化は避ける |
| 明るい本文＋濃色の冒頭 | 製品画像と短い訴求を見せる構成候補。内容の具体像と自分への利点が伝わる場合に比較し、サイト紹介だけの帯にしない。記事外への拡張はしない |

純白/青緑/暖色/濃色帯のいずれも単独で成果を保証しない。代表画面で本文の読みやすさ、情報の優先順位、製品画像の見え方、選びやすさ、PC/スマホのコントラストとフォーカス、既存の承認済み強調との調和を比較する。読みやすい案の中でToolArcらしい配色を具体化し、実際の差分を提示する。収益性の優劣は本番後の読まれ方・行動とデータの範囲で判断する。

Nottaは公式画面→用途別おすすめ→詳しい理由というN35の説明順を維持する。公式画像に写る製品UIの色や素材自体は変更しない。使い方の折りたたみの白背景は既存の個別承認を保持し、本文のお得情報3枠も自動撤去/全面塗替えしない。

参考：[NN/gの視覚的階層](https://www.nngroup.com/articles/visual-hierarchy-ux-definition/)は大きさ・配置・余白などによる情報の優先順位を考える材料、[右レールの視線調査](https://www.nngroup.com/articles/fight-right-rail-blindness/)は広告のような見せ方への注意の材料とする。これらがToolArcの特定配色の収益効果を検証した証拠とは扱わない。
