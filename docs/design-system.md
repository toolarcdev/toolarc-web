## TOPページ

TOPはA系の誌面型を基準とする。全幅の濃い青緑の紹介帯と明朝体の見出し、小型の記事カード、記事への直接移動、ジャンルへのページ内ジャンプを組み合わせる。

- TOP内のジャンル見出しの下に記事を並べる。PCではAI学習の4記事を横並びにするAの配置を基準にし、狭い幅では列を減らして縦に並べる。Bのジャンル左右交互配置は採用しない。
- 媒体紹介は濃い青緑の全幅帯、本文側は明るい背景と濃い文字。冒頭・ジャンル等の見出しはA3の明朝体を基準にし、本文・記事カード・ナビゲーションを一律に明朝体へ変更しない。
- 3ジャンル・8ページ（LP5本＋通常記事3本）を紹介し、各ページへワンクリックで直接移動できるようにする。ジャンルページなどを間に挟まない。
- 冒頭の紹介帯に3ジャンルへの控えめなページ内ジャンプリンクを置く。同一TOP内の各見出しへ移動し、常時表示のメニューにはしない。記事への直接移動と両立させる。
- 記事はカード型にし、画像・タイトル・説明・余白を含むカード全体を1つのリンクにする。カード内の「広告」ラベルと「記事を読む＋矢印」は表示しない。キーボードでもカードを選んで記事へ進めるようにする。カード内の方針は、サイト下部の広告利用説明や記事・LP側の開示は変更しない。
- カードの文字サイズを縮めず、画像の高さ・重複するキャッチ文・説明の長さ・内側余白を整理してコンパクトにする。ラベル・サービス名/記事タイトル・短い説明に絞り、内側余白は14pxを基準とする。
- ChatGPT・Cursor・Obsidianを補助案内とし、各名前の横に矢印は付けない。名前・説明・リンクは保持する。全シリーズをTOPへ並べず、網羅的な案内はシリーズ一覧に任せる。更新記事は下部に数件置く。
- フッターの紹介は「AIツールの使い方や、学び方を紹介しています。」を現行文とする。「日本語メディア」という自称は使用しない。公開面の語彙については `docs/ai-context/editorial-room-terms.md` の文脈付きの記録を参照する。
- 読者にも広告担当者にも自然に媒体の実態が伝わる紹介にする。ASPや案件に合わせて媒体紹介を変えず、審査通過率を設計目標・達成条件に置かない。
- 文案・掲載画像・色値・文字サイズ・余白・ヘッダー/フッター・更新記事の選定基準等は、採用済み条件を維持して採用した構成から調整する。比較用ラベルや仮文案をそのまま公開仕様にしない。

### 実装の担当と境界

- app/page.tsx と app/page.module.css に構成・選定記事・スタイルを集約する。記事本文、案件レジストリ、シリーズ一覧、共通計測を同時に変更しない。
- TOP専用ヘッダー/フッターと共通部品が二重表示されないよう、SiteChromeのルート判定を維持する。下部の広告利用説明と既存のポリシー導線を保持する。
- カードは内部ページへのリンクとし、LPの事前読込みやアフィリエイトURLの直置きを行わない。
- TOP専用画像はpublic/images/home/の縮小済みWebPを使用し、元画像を保持する。最大幅960pxを基準とし、縮小済み画像を動的に再変換しない。
- 最近の記事は記事登録の公開日順で3件取得する。サンプルの固定3件や更新日順に置き換えない。

## 記事ページ

明るい本文と濃色の全幅タイトル帯、本文と連動したタイトル列を基本とする。記事別の文字数判定・固定高さ・手動改行による例外を増やさない。記事の配色ルールをTOP・一覧・静的ページへ一括展開しない。

- 白または温かみのある明るい背景と黒に近い文字を中心にし、細い中立色の罫線と余白で情報を区切る。アクセントはリンク・開閉・読者の判断を助ける箇所など役割を定める。本文や面全体を一律に青くしない。
- タイトル・公開日/更新日・短い導入を読み始めの中心にする。大きな青いサイト紹介帯、青い囲みのdescriptionカード、冒頭に密集するタグ表示を整理する。
- SEO用descriptionと本文導入の役割を分ける。長いdescriptionを枠付きで本文と重複表示しない。メタデータ・タグの元データは削除しない。
- 記事本文内の結論や用途別案内は、その記事の読者課題に合わせる。全記事へNottaのC案・公式画面・3行のプラン選択を必須化しない。
- 制作/運営説明、出典・クレジット・免責は下部へ。広告開示そのものは消さず、既存の下部表記と重複/不足を照合して集約する。読者の判断に必要な比較条件は本文に保持する。
- 収益導線、アフィリエイトの実装方針、リンク先、計測イベント、SEOのtitle/description/canonical/OG、公開日データは変更しない。計測の都合でUIを増やさない。
- 共通部品の変更時は利用箇所を調べ、ブログ記事だけに適用する境界を確定する。通常記事・hands-on・既存の折りたたみをPC/スマホで確認し、意味のあるフォーカス・コントラスト・改行・表幅を維持する。

### 列寸法とタイトル

- 記事レイアウトは最大1024px。1024px以上で右レール220px・列間48pxを使用し、本文列は残りの幅に収める。
- 帯の背景は画面幅いっぱいに置き、帯内の題名・日付の左右端は本文列へ揃える。帯の高さは内容と余白から決める。
- 列寸法の変更ではArticlePage.module.cssとRichArticleLayoutの両方を確認する。別の固定値を片方へ追加しない。
- 日本語の自然な折返し、スマホの見出し・日付・本文の余白、既存の目次追従を維持する。

### 読みやすさと判断のしやすさ

| 役割 | 見せ方 |
|---|---|
| 読み進める | 明るい本文背景、濃い文字、適切な本文幅・行間・余白 |
| 興味を持つ | 公式画像、具体的な利用場面、内容が分かる見出し |
| 自分に合うと判断する | 用途別おすすめ、比較と金額差、次の行動 |

色だけで訴求や収益性を保証しない。Nottaでは公式画面→用途別おすすめ→詳しい理由の順を維持し、製品UIの色や素材自体を変更しない。使い方の折りたたみの白背景と、節約額を示す3枠を自動撤去・一括塗替えしない。

### 免責・出典の補足欄

- article-notes:start/endで明示した範囲だけをArticleBodyの補足asideへ振り分ける。末尾の段落数や文字列で自動判定しない。
- 本文17pxに対し補足13px・行高1.7・灰緑色。細い上罫線と段落間12pxで本文から区別する。
- 制作/運営説明、未実測範囲、クレジット、出典は補足欄へ集める。読者の比較・判断に必要な条件は本文側に残す。
- 既存記事への適用は本文リライトに合わせる。全記事への一括追加や補足欄だけの独立タスクを作らない。詳細は [writing-rules.md](./ai-context/writing-rules.md)「既存記事への補足欄の適用」。

### おすすめ表と画像説明

- article-recommendations:start/endで囲んだ表は、左に用途、右におすすめと理由を置く2列構成とする。600px以下では縦並びとし、見出しは支援技術向けに保持する。多列の数値比較表へそのまま流用しない。
- 短い要約と詳しい説明を並べる2列の表は、`article-summary-table:start/end` で対象の表を囲む。左列は1行で表示し、右列は画面幅に応じて折り返す。スマートフォン幅でも左列が1行に収まり、右列を横スクロールせず読めることを確認する。
- キャプションは画面や比較の内容を伝え、画像と一体にする。制作元・著作権・未実測の説明は補足欄へ。キャプション14pxと補足欄13pxを同じ役割へ一括統合しない。
- 文言・画像データと描画処理、記事の範囲指定と共通CSSの責務を分ける。

## パンくず横の広告ラベル

読者向けの本文と広告開示を分け、「広告」はパンくずと同じ行の本文幅右端へ置く。

- 対象記事の冒頭に `<!-- article-ad-label -->` と次行の `広告` を1回指定。記事page.tsxの `adLabelPattern` / `hasAdLabel` で読取り、本文からこの組を除去する。汎用の新規解析関数は追加していない。
- `ArticlePage.module.css` の `breadcrumbsWithAd` が横並び・中央揃え・間隔16pxとタイトルの省略を担当。`articleAdLabel` は縮小/折返しを防いで右寄せする。
- `breadcrumbsWithAdAndRail` は1024px以上の右レールありで、既存のレール幅/列間隔の変数を引いた本文列幅へ合わせる。CSSの自作関数や新しい列寸法定数は追加しない。
- 広告は免責/出典欄と同じ13px・文字色 `--article-muted`（#59645f）・行高1.7。同じ文字スタイル宣言を共有し、`notes` の箱・上罫線・余白を広告へ適用しない。本文17pxは保持。
- 指定のない記事は変更しない。共通Breadcrumbsコンポーネントとその構造化データは維持し、広告をパンくずの階層に加えない。
- 明示指定をコード例や折りたたみ内へ入れる使い方は未検証。シリーズバッジ併用、指定あり/レールなしへの再利用は別途確認する。

詳細な使い方と処理の担当はVaultの「ToolArc記事UI_共通部品と表示処理の管理台帳」を参照する。

## 右サイドバーと収益導線の境界

右側の案内の採否・ROI/計測の前提はVault「ToolArc右サイドバー_読者支援と収益導線の設計」。広告の可否はpolicy.ts、選定はrail-pool.tsを正とし、共通デザイン整理を理由に広告枠・プール・計測を変更しない。

## 変更時の確認基準

- buildと変更対象に適した検証を行う。実行結果・確認画像・操作数はVaultへ記録する。
- PCと320/375/414/768/1024/1280px等の境界幅で、重なり・横はみ出し・画像・文字の折返しを確認する。見出しは短い/長い題名、通常/hands-on、明示指定あり/なしで確認する。
- 共通部品では対象外ページ、範囲指定では未指定部分への影響を確認する。変更する機能に応じてキーボード操作・リンク先・フォーカス・コントラストも確認する。
- パンくず横の広告は、中央揃え、右端、間隔16px、タイトル省略、本文側との二重表示/内部目印の露出がないことを確認する。
- 表示の検証をアクセス・収益効果の証明に置き換えない。対象PRへの人間のマージ承認と本番確認は別の工程として維持する。
