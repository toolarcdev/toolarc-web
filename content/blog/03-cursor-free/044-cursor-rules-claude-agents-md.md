# CursorのRules・CLAUDE.md・AGENTS.md｜どれを使うか

Cursorを使い始めてしばらくすると、プロジェクトの中に`.cursor/rules`、`AGENTS.md`、`CLAUDE.md`という似た名前のファイルが並ぶことがあります。どれもAIへの指示ファイルに見えるため、最初は何をどこに書けばいいのか迷うはずです。

わからないまま作業を進めると、同じ指示を複数のファイルにコピーしてしまいがちです。結果として内容が少しずつ食い違ったり、読み込ませるtoken（トークン）の量が余計に増えたりする。公式の「このファイルが常に優先される」という順位が明確に示されているわけではないため、迷いが解消しにくいという事情もあります。

`.cursor/rules`の具体的な書き方やテンプレートは、別記事のRules Tipsで扱っています。本記事の役割はそこではない。3ファイルの立ち位置を比較し、どれを先に置くべきかを決めることです。

> **今日の結論**
>
> - 公式の「このファイルが常に勝つ」という優先順位は、本記事では断定しません
> - Cursorだけで効かせたい手順やパスの制約は、Project Rules（`.cursor/rules/`）に書きます
> - リポジトリ横断の方針・禁止事項・委譲の入口は、`AGENTS.md`に寄せます
> - `CLAUDE.md`はClaude Codeを使うときだけ用意し、同じ文言を3か所にコピーしません
> - 書き方が次の課題ならRules Tips、読む順が曖昧ならHubへ進んでください

## 3ファイルの役割比較｜Rules・CLAUDE.md・AGENTS.md

CursorのProject Rules（プロジェクトのルールファイル。実体は`.cursor/rules/`）、`CLAUDE.md`、`AGENTS.md`は、それぞれ効く範囲と役割が異なります。まずは表で全体像を押さえます。

| ファイル名                        | 役割                                                                                          | 向く状況                                                  | 向かない状況                                                                     |
| --------------------------------- | --------------------------------------------------------------------------------------------- | --------------------------------------------------------- | -------------------------------------------------------------------------------- |
| Project Rules（`.cursor/rules/`） | Cursor向けの前提指示。常時・パス指定・手動など、効かせ方を分けやすい                          | Cursorだけで守らせたい手順やファイル種別の制約            | リポジトリ全体の方針の正本にする、他ツールと共有したいルールの唯一の置き場にする |
| `AGENTS.md`                       | 複数ツールが参照しうる共通ルールの入口。詳細を他ファイルへ委譲しやすい                        | 方針・禁止事項・「どこを正本とするか」を1か所にまとめたい | Cursor固有のパス指定ルールをすべてここに書く、同じ長文をRulesと二重に持つ        |
| `CLAUDE.md`                       | Claude Code側で参照されやすいプロジェクトメモ（リポジトリによって扱いが変わる場合があります） | Claude Codeを常用し、Cursor用とは分けて管理したい         | Cursorしか使わない、`AGENTS.md`と同じ文言のコピー置き場にする                    |

表の「役割」は実務上の目安です。公式の対応関係や優先順位を示すものではありません。

公式ドキュメント（CursorのRules／Project Rules関連ページ）では、配置やスコープの説明は見つかりますが、3ファイル間の読み込み順を明言した記述までは確認できていません。筆者がToolArcの公開リポジトリで実装した範囲では、方針の入口を`AGENTS.md`に置き、Cursor固有の指示は`.cursor/rules/`へ分け、`CLAUDE.md`は使う場合だけ用意する、という分け方に落ち着いている。あくまで一つの実務例であり、公式の対応関係として書いているわけではありません。

## 向く人／向かない人｜どれを先に置くか

比較表の列をそのまま繰り返す代わりに、読者の状況で振り分けます。

**Project Rules が向く人**

- Cursorの Agent にだけ、パス単位の制約を効かせたい人
- 全体方針は別ファイルにあり、Cursor固有のルールだけ足したい人

**Project Rules が向かない人**

- まだCursorを常用しておらず、先にリポジトリの入口方針だけ決めたい人
- 書き方やテンプレートが主目的の人（その場合はRules Tipsが向いています）

**`AGENTS.md` が向く人**

- Cursor以外のツール（Claude Codeなど）からも同じ禁止事項・委譲ルールを見たい人
- 「正本はどこか」を1ファイルにまとめたい人

**`AGENTS.md` が向かない人**

- Cursorのglob指定や手動ルールの置き場にしようとしている人
- 入口ファイルに長文の手順を全部貼り、委譲先を持たない人

**`CLAUDE.md` が向く人**

- このリポジトリでClaude Codeを使う人
- Cursor用の指示と文言を分けたい人（コピーではなく、入口＋差分という形にしたい人）

**`CLAUDE.md` が向かない人**

- Cursorのみを使っていて、ファイルを増やす理由がない人
- 「`CLAUDE.md`が常に優先される」と読める公式の材料を求めている人（本記事では断定しません）

迷ったときの目安：方針の入口は`AGENTS.md`、Cursor固有はRules、Claude Codeを使うときだけ`CLAUDE.md`

## 同じ指示を二重に書かない実務

Rules Tipsの失敗パターン集はここでは扱いません。本記事で足すのは、同じ意味の指示を2ファイルに置かない手順だけです。

1. 正本を1つ決めます。方針は`AGENTS.md`、Cursor固有は`.cursor/rules/`、Claude Code向けの差分は`CLAUDE.md`、という分け方が一つの目安になります。
2. 正本以外のファイルには、委譲であることが分かる1行だけを残します。本文をまるごと二重に貼りません。
3. 指示を直したときは、同じ禁止事項や同じ手順が他のファイルに残っていないかを確認します。
4. 確認は新規チャットで行うと、古い指示のキャッシュに引っ張られにくくなります。

ToolArcの公開リポジトリでは、ルートの`AGENTS.md`を入口にし、記事ドメインの詳細は別ディレクトリへ委譲、Cursor向けの公開ルールは`.cursor/rules/`に置く、という分け方を採用しています。読者のリポジトリにそのままコピーする前提の型ではなく、あくまで分け方の一例です。

二重管理が起きると、指示の食い違いに加えて、読み込ませるtoken量が増えやすくなります。

## 次に読む｜書き方（Rules Tips）かHubか

本記事は「どれを置くか」の判断を、表と向く人の整理だけで完結させています。次に読みたい記事は、目的によって分かれます。

- `.cursor/rules`の具体的な書き方やテンプレート、失敗パターンまで知りたい場合は、[Rules Tips](/blog/cursor-rules-file-tips)が無料で読めます。本記事のテンプレートは繰り返さず、書き方はそちらに譲ります。
- Cursorシリーズを読む順に迷っている場合は、[Hub記事](/blog/cursor-free)から入るとたどりやすくなります。
- 拡張の入れすぎ判断は[拡張機能のおすすめ](/blog/cursor-extensions-recommended)、インデックスの詰まりは[コードベースインデックスの確認](/blog/cursor-codebase-indexing-basics)へ。
