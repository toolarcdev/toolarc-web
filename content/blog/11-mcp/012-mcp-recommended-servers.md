# おすすめMCP Server一覧｜開発者が最初に試す選定枠

MCPの用語は分かったが、どのServerから足せばよいか分からない。カタログが多すぎて、権限リスクも気になる。そんな段階向けの選定メモです。

本記事は、開発用途で「最初の1本」を決めるための枠組みと、触れやすい候補の見方をまとめます。個別の長い設定手順は、各Client／Server向けの記事で扱います。

> **今日の結論**
>
> - 最初は、いま使っているClient（Cursor／VS Code／Claudeなど）向けに公式の導入手順があるServerを1本だけに絞ると、つまずきの切り分けが楽です。
> - ファイル／ブラウザ／GitHub／検索など、用途カテゴリで候補を分け、権限が広いものほど後回しにします。
> - おすすめは「必ず入れるべき」リストではなく、試す順番の提案です。製品の提供状況は変わります。
> - Client（Cursor／VS Code／Claude）で設定キーやパスが違うため、同じJSONを無検証で使い回さない方が安全です。
> - カタログのワンクリック導入は便利ですが、出典と権限範囲を確認してから採用してください。

本記事は、筆者が公式ドキュメントと公開情報を確認した内容をもとに整理しています。個別Serverの動作確認や、候補の網羅はしていません。

## 最初の1本を決める判断枠

選定で先に決めるのは、Server名より次の3点です。

| 観点   | 質問                                               | 失敗しやすい例                         |
| ------ | -------------------------------------------------- | -------------------------------------- |
| Client | 今いるのはCursor／VS Code／Claudeのどれか          | 別ClientのJSONをそのまま貼る           |
| 用途   | 今日試したいのはファイル／GitHub／ブラウザのどれか | 用途未定のまま権限の広いServerを入れる |
| 権限   | 読み取りだけで足りるか、書き込みが必要か           | 最初から広いトークンを渡す             |

シリーズの入口は[MCPガイド](/blog/mcp-guide)です。用語がまだ曖昧なら、先に#1〜#4を読む方が結果的に早いです。

## 用途別の候補の見方

「おすすめ」は固定ランキングではなく、用途ごとの入口です。提供状況は変わるため、採用前に公式を再確認してください。

| 用途                  | まず見る候補の例                | ToolArcでの次の記事                                                            |
| --------------------- | ------------------------------- | ------------------------------------------------------------------------------ |
| GitHub操作            | 公式 GitHub MCP Server          | [GitHub MCP Serverの設定](/blog/mcp-github-server-setup)                       |
| VS Code上での追加全般 | VS Codeのギャラリー／`mcp.json` | [VS CodeのMCP設定](/blog/mcp-vscode-setup)                                     |
| Cursor上での追加全般  | Customize／`mcp.json`           | [CursorのMCP設定](/blog/mcp-cursor-setup)                                      |
| Claude Desktop／Code  | Desktop JSON／`claude mcp add`  | [Desktop](/blog/mcp-claude-desktop-setup)／[Code](/blog/mcp-claude-code-setup) |
| 接続方式の迷い        | stdio／SSE／HTTPの違い          | [stdioとSSE](/blog/mcp-stdio-vs-sse-transport)                                 |

ファイル系・ブラウザ系・検索系などは、Clientのギャラリーや公式レジストリに候補が並びます。名前が似ていても配布元が違うことがあるため、「公式か／誰が配布しているか／必要な権限は何か」をセットで見てください。

## 入れない方がよい候補のサイン

次に当てはまる場合は、採用を急がない方が安全です。

- 説明が薄く、出典やリポジトリが追えない
- 要求権限が極端に広い（理由の説明がない）
- 古いnpmパッケージ名だけが残り、公式が非対応を案内している
- 自分のClient向けの設定例が一切ない

上のどれかに当てはまるなら、そのServerは後回しにするか、権限と配布元を公式ドキュメントで突き合わせてからにしてください。シリーズ共通の注意は[MCPガイド](/blog/mcp-guide)にもあります。

## Client差分を忘れない

同じServerでも、設定の書き方はClientで違います。

| Client         | つまずきやすい点                        | 正本記事                                         |
| -------------- | --------------------------------------- | ------------------------------------------------ |
| VS Code        | キーが`servers`（`mcpServers`ではない） | [VS CodeのMCP設定](/blog/mcp-vscode-setup)       |
| Cursor         | プロジェクト／グローバルの優先          | [CursorのMCP設定](/blog/mcp-cursor-setup)        |
| Claude Desktop | Extensionsと設定JSONの役割              | [Claude Desktop](/blog/mcp-claude-desktop-setup) |
| Claude Code    | `claude mcp add`とスコープ              | [Claude Code](/blog/mcp-claude-code-setup)       |

「一覧で選んだあと、どのClient記事に進むか」を先に決めると、別Client向けの設定をそのまま貼って動かなくなるミスが減ります。

## よくある質問（FAQ）

**Q1. おすすめを全部入れるべきですか？**

いいえ。最初は1本、できれば読み取り中心からが安全です。増やしすぎると、どのServerが原因か切り分けにくくなります。

**Q2. ギャラリーの上位＝安全ですか？**

順位や人気は安全性の証明ではありません。公式案内・権限・配布元を個別に確認してください。

**Q3. この一覧はいつ最新になりますか？**

固定の最新一覧ではありません。Serverの追加・廃止は速いため、実装直前に公式とClientのギャラリーを再確認してください。
